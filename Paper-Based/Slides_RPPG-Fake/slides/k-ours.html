06 · การวิพากษ์การวิจัย · Limitation ของเรา

สิ่งที่เราทำ

ข้อจำกัดของการทดลองเรา

เครื่องรันไม่ไหว

• Laptop RTX 5050 8 GB · RAM 16 GB

• รัน 2 dataset พร้อมกัน → RAM เต็ม ช้า 3 เท่า และ crash

• train ใหม่ทั้งชุด ≥ 6 ชม. → 3 seeds (paper 5) · RL 5 epoch · จำกัดจำนวน action

ข้อมูลไม่เหมือน paper

• GossipCop / PHEME ดึงเนื้อข่าวและภาพเอง เก็บเฉพาะข่าวที่ครบ → ขนาดและสัดส่วน class ต่างจาก paper

• PolitiFact ไม่มีภาพ · test แค่ 96 ข่าว

• ใช้ UU แทน PNU · ใช้ CLIP แทน encoder ของ paper

การทดลองยังไม่ครบ

• Table IV (Random / Similarity) ยังไม่ได้รันใหม่หลังแก้ bug

• 3 seeds ไม่พอทดสอบนัยสำคัญ

• demo เหตุการณ์ใหม่มีแค่ 64 ข่าว

ความผิดพลาดของเราเอง

• bug embedding ยุบอยู่ตั้งแต่รอบ 1 · มาเจอในรอบ 8

• ตัวเลขรอบ 1–7 ใช้เทียบกับ paper ไม่ได้

• บทเรียน: ตรวจ embedding ก่อนดู accuracy

ข้อจำกัดทั้งหมดบันทึกใน HANDOFF.md ข้อ 6 และ Code_RPPG-Fake/RUNNING.md ข้อ 5

ข้อจำกัดของเราเองมีสี่ด้าน หนึ่ง เครื่องที่ใช้เป็น laptop GPU 8 GB และ RAM 16 GB เมื่อรันสอง dataset พร้อมกัน RAM เต็ม ช้าลงสามเท่าและ process crash จึงต้องรันทีละงาน และการ train ใหม่ทั้งชุดใช้เวลามากกว่าหกชั่วโมง เราจึงลดเหลือ 3 seeds จาก 5 ใน paper, RL 5 epoch และจำกัดจำนวน action ต่อ step สอง ข้อมูลไม่เหมือน paper เพราะต้องสร้างเอง สาม การทดลองบางส่วนยังไม่ได้รันใหม่หลังแก้ bug และจำนวน seed น้อยเกินจะทดสอบนัยสำคัญ สี่ bug ที่ทำให้ embedding ของ user ยุบเป็นค่าเดียวอยู่ใน code ของเราตั้งแต่รอบแรกและเพิ่งพบในรอบ 8 ทำให้ตัวเลขรอบก่อนหน้าเชื่อไม่ได้ บทเรียนคือควรตรวจคุณภาพ embedding ก่อนดู accuracy
